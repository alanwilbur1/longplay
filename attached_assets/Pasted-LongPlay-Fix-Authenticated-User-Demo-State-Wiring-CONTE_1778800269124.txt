LongPlay — Fix Authenticated-User / Demo-State Wiring

CONTEXT
LongPlay is a Next.js 16 (App Router) + Supabase project. OTP email auth is working — users can request a code, verify it, and a Supabase session is established. However, after successful login the app still presents the seeded "Elena / Nocturnal Romantic" demo identity, and unauthenticated users can still reach the authenticated app shell by virtue of a stale localStorage onboarding flag.

The diagnosis is complete and approved. This task is state/auth wiring only. Do NOT redesign UI, do NOT change typography, colors, layout, animation, spacing, or the LongPlay editorial aesthetic. Do NOT add new screens. Do NOT remove the seeded ambient/editorial content that lives in room, club, and album screens.

Work on a new branch off origin/main:
    git checkout origin/main
    git checkout -b fix/auth-state-wiring

SCOPE — APPROVED FIXES
==============================================================

1) ProtectedLayout must be auth-aware
   File: components/protected-layout.tsx
   - Currently it ONLY checks isOnboardingCompleted() from localStorage.
   - Change it to consult useAuth() (from components/auth-provider.tsx) and treat the Supabase session as the source of truth.
   - Decision matrix the guard must implement (do not change the visual loading/redirecting states, only the routing logic):
       a. authLoading === true                              → show loading state (existing UI)
       b. PUBLIC_PATHS match (/onboarding, /auth, /share)  → allow
       c. isAuthenticated === false                         → redirect to /onboarding (regardless of localStorage)
       d. isAuthenticated === true                          → allow
   - The localStorage flag alone must never grant access. Do not delete the localStorage helpers; they remain useful as a per-device "completed once" hint, but they are no longer the gate.
   - Preserve the existing 3-second timeout safety fallback behavior and the dev-mode debugStep readout.

2) Remove the onboarding bypass in CompleteStep
   File: components/onboarding-screen.tsx (CompleteStep, ~line 940–1208)
   - The large "Enter LongPlay" button at the top of CompleteStep currently calls onFinish() without requiring authentication. This is the bypass.
   - Required behavior:
       • Before OTP verification succeeds, the "Enter LongPlay" button must be disabled (keep it visible so the layout does not shift; render it as disabled / muted using existing disabled styles already present in this file). Tooltip or helper copy underneath: "Verify your email to continue." Match existing muted-helper text styling — do not invent new visual treatments.
       • After OTP verification succeeds (phase === 'success'), the existing setTimeout(onFinish, 1400) flow is the only path to onFinish().
       • handleComplete() must additionally guard: read the current Supabase session via getSupabaseBrowserClient().auth.getSession() and only call completeOnboarding() + router.push('/') if a session exists. If no session, set an inline error using the existing friendlyAuthError() copy pattern and stay on the step.
   - Do NOT change the visual structure of CompleteStep, the email form, the OTP form, the success state, or the resend / change-email controls.

3) Sign-out cleanup
   File: components/profile-screen.tsx — handleSignOut (~line 197–203)
   Also add a small shared helper if convenient (e.g. lib/auth/sign-out.ts) but it is fine to inline.
   On sign-out, in this exact order:
       a. await supabase.auth.signOut() on the browser client (clears the implicit-flow session in localStorage under sb-<ref>-auth-token)
       b. resetOnboarding() from lib/onboarding-state.ts (clears longplay_onboarding)
       c. sessionStorage.removeItem('longplay_onboarding_synced') (the key used by components/onboarding-sync.tsx)
       d. router.push('/onboarding')
   Verify there are no other longplay_* keys being written; if any are found during implementation, clear them too.
