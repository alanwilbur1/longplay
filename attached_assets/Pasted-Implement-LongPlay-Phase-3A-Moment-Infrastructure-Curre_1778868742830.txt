Goal:
Build the foundational Moment system exactly aligned to the Moment Model and Technical Architecture.

Scope:

1. Add schema migration:
Create lib/schema-phase3a-moments.sql

Include:
- moments table
- moment_visibility_history table
- participation_events table
- required enums:
  - moment_type: mark, annotation, reflection, prompt_response, rating, reply, save
  - moment_visibility: private, club, connection, public
  - participation_event_type
- constraints:
  - every moment has member_id, type, created_at, created_local_time, visibility, album_id, content
  - timestamp_ms requires track_id
  - prompt_response requires cycle_id and prompt_id
  - reply requires parent_moment_id
  - default visibility = private
- indexes:
  - moments(member_id, created_at)
  - moments(album_id, created_at)
  - moments(cycle_id, created_at)
  - moments(parent_moment_id)
  - moments(member_id, type)
- RLS:
  - owner can select own moments
  - owner can insert own moments
  - owner can update visibility only through controlled path if possible
  - no in-place content edits
  - club-visible moments readable only by members of that cycle after discussion phase opens, if current schema supports that
  - if discussion gating cannot be fully implemented yet, default to owner-only and document the limitation

2. Server actions:
Create lib/actions/moments.ts

Implement:
- createMoment(input)
- branchMoment(parentMomentId, input)
- updateMomentVisibility(momentId, newVisibility)
- softDeleteMoment(momentId)
- listMyMoments(filters?)
- getMyMoment(momentId)

Rules:
- no in-place content editing
- revision = new Moment with parent_moment_id
- visibility changes write moment_visibility_history
- all actions require authenticated Supabase user
- user can only mutate their own Moments
- return clear success/error objects

Keep helper outputs typed and stable.
